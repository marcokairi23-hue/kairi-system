# מערכת קאירי — רקע עסקי ומוצר

## 1. הרקע העסקי

**העסק:** מרקו קאירי — וילונות ובדים בהתאמה אישית (עסק משפחתי).

**המטרה:** להחליף גיליון Google Sheets ("Tofsy") שבו מנוהלות ההזמנות היום, ולאחד שלוש אפליקציות שנבנו ב-Base44/Lovable (MK MINI CRM, FABRIKAIRI, KAIRI CURTAINS NEW TOFSY) למערכת אחת.

**המניע העיקרי (חשוב מאוד):**
> "המערכת צריכה להציג **חותמות זמן על פעולות של כל אחד**, כדי שהעובדים לא יזרקו אחריות אחד על השני."

זה הלב. לא תחכום — **שקיפות ואחריות.**

**המשתמשים (3-7):**
| שם | תפקיד | מה עושה |
|---|---|---|
| מרקו | אדמין | בעל העסק |
| גיא, רן | סוכני שטח | ממלאים טופס הזמנה אצל הלקוח |
| אליזבט | משרד | קליטה, גבייה, הזמנה מספקים |
| יוני | גוזר | גוזר בד, שולח למתפרה |

**שרשרת ההזמנה בפועל:**
1. **סוכן** ממלא טופס אצל הלקוח → מעביר לגבייה
2. **משרד** — גובה תשלום, מזמין מוצרי הצללה מספק (WhatsApp), מעביר לביצוע
3. **גוזר** — מדפיס הוראות עבודה, גוזר בד, משייך למתפרה
4. **מתפרה** — אוספת, תופרת, מחזירה
5. **התקנה** — רק כשכל ההזמנה מוכנה (לא בסבבים)

## 2. החלטות שנסגרו (אל תשנה בלי לשאול)

| נושא | ההחלטה |
|---|---|
| **תמחור** | **אין מנוע תמחור.** הסוכן מקליד מחיר לכל פריט ידנית. "חישוב אוטומטי" = סכימה בלבד |
| **הצעה מול הזמנה** | ישות אחת (`orders`) עם `is_quote` + סטטוס. לא שתי טבלאות |
| **מספור** | רץ מ-9000, מוקצה בשרת (`allocate_order_number`) |
| **התקנה** | נגבית בנפרד — **לא נכללת** בסה"כ האוטומטי |
| **הזמנה חלקית** | פס התקדמות, **לא** סטטוס נפרד |
| **התקנה** | רק כשכל ההזמנה מוכנה — לא בסבבים |
| **חתימה** | כרגע טקסט (שם). ציור על מסך — עתידי, אופציונלי |
| **צריכת בד** | כלל התחלתי: `רוחב × 3` עד גובה 3.00 מ׳. יוחלף באלגוריתם |
| **שפה** | עברית בלבד, RTL |

**מונחים מקצועיים:**
- **שטייף** — הקפל העליון של הווילון (סוג תפירה)
- **מכפלת** — החלק התחתון, ברירת מחדל 10 ס"מ
- **חצוי** — האם הווילון נפתח מהאמצע לצדדים (2 כנפיים) או כנף אחת
