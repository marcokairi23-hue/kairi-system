## 6. מודל הסטטוסים

**סטטוס הזמנה:**
```
quote (הצעת מחיר)
  → pending_payment (ממתין לגבייה)
  → ready (חדש לביצוע)
  → in_production (בייצור)
  → ready_for_install (מוכן)
  → completed (הושלם)
+ cancelled
```

**סטטוס פריט:**
```
new (חדש) → cut (נגזר) → sewing (במתפרה) → ready (מוכן) → installed (הותקן)
+ cancelled
```

**סנכרון דו-כיווני (מיושם):**
- קידום הזמנה → דיאלוג: "לעדכן גם את N הפריטים ל-X?"
- כל הפריטים באותו סטטוס → דיאלוג: "לקדם את ההזמנה ל-Y?"

**הזמנה חלקית:** לא סטטוס נפרד — מוצג כ**פס התקדמות** (`4/6 מוכנים`).

## 8. ⚠️ מה קרה בספרינט האחרון (חשוב לדעת!)

נבנה מודול ייצור (ספקים, מתפרות, מסלולי ייצור, צ'קליסט קליטה, מסך גזירה) — **ובוטל.**

**הסיבה:** יותר מדי תחכום, סטייה מהמטרה העיקרית. הקוד הוסר, המערכת חזרה ל-V6.

**מה שנשאר ב-DB (לא מזיק):**
- ערכי enum: `ready_for_install` (ב-order_status), `ordered_from_supplier`, `arrived` (ב-item_status) — Postgres לא מאפשר להסיר ערכי enum
- עמודות ב-`order_items`: `production_route`, `supplier_id`, `date_cut`, `date_sent`, `date_target`, `date_returned`, `date_installed` — יושבות ריקות
- טבלת `suppliers` — ריקה (או נמחקה)

**מה שהוסר:** העמודות `intake_by`, `intake_at`, `date_target` מ-`orders` — הן יצרו **קשר כפול ל-`profiles`** ושברו את השאילתות.

**🔧 תיקון קריטי שבוצע בקוד:**
כל שאילתה שמושכת `profiles` מ-`orders` **חייבת** לציין את הקשר במפורש:

```typescript
// ❌ שגוי — עמום
.select('*, profiles(full_name), order_items(*), payments(*)')

// ✅ נכון
.select('*, profiles!orders_agent_id_fkey(full_name), order_items(*), payments(*)')
```

**זה קיים כיום ב:** `OrdersList.tsx`, ואולי צריך גם ב-`OrderDetail.tsx` ו-`EditOrder.tsx`.

## 12. תזכורות תפעוליות

**מיגרציה ב-Supabase:** SQL Editor → New query → הדבק → Run
**אם enum נוסף ולא עובד:** הרץ את הקובץ פעמיים (Postgres דורש commit בין הוספה לשימוש)
**רענון schema cache:** `NOTIFY pgrst, 'reload schema';`
**Deploy:** `git add . && git commit -m "..." && git push` → Cloudflare בונה אוטומטית
**באג נפוץ:** popup blocker בהדפסה — הפתרון הוא Blob URL, לא `window.open('')`
